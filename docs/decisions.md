# Architecture decisions

The input specifications are preserved in master-build-prompt.md and workflow-plan.md. The architecture supplied in chat is implemented as an application-owned controller around four sequential CrewAI task invocations. Ordinary application code enforces state transitions, source writes, command profiles, retry budgets, evidence and acceptance.

Python 3.12 is the supported runtime. Generated projects use the standard library, pytest and Ruff only. Additional dependencies, uploaded repositories, arbitrary configuration files, Dockerfiles, shell commands and deployments are outside v1. A developer response is a complete source snapshot, allowing safe file deletion and reproducible diffs against an empty project.

CrewAI roles run in disposable host subprocesses with no shell, filesystem or code-execution tools. Provider calls cannot execute generated code. Cancellation/deadlines kill the model process; fixed Docker calls run in threads with cooperative cancellation and mandatory finalizers. A role invocation has one schema-repair or provider retry; model/provider and framework retries have small fixed limits. The role-call count is an invocation budget, not a precise count of HTTP requests or a monetary cap. Per-response token output is capped at 16,000. Configure provider-side spend quotas for strict cost control.

The sandbox uses a short-lived trusted staging container and a per-check Docker volume for validated source. The execution container mounts only that volume, read-only. Code runs in a 32 MiB tmpfs. No host directory or Docker socket is mounted into either sandbox container. Source is never copied back from the container; only bounded logs and exit/resource evidence return. Static checks are also container-only. The runner resolves the configured locally built image to its ID; it never pulls an image named by an agent.

SQLite and an asyncio queue are suitable for one local backend process. Admission and enqueue are atomic in the event loop. The queue and worker counts are bounded. An OS-released file lock enforces a single API/CLI controller per data directory, before restart recovery can mutate runs. Active runs fail on restart and abandoned labeled Docker resources are removed before accepting new work when Docker is reachable. A persisted random instance ID scopes resource ownership per data volume, including independent Compose installations that both use `/data`. Do not use uvicorn multi-worker mode. A durable queue and PostgreSQL are future multi-user work.

The backend and source generator are trusted control-plane code; source/log content is untrusted. API errors use safe messages. Frontend content is React-escaped; artifact responses are plain text with nosniff. Browser requests use a same-origin Next.js proxy. Compose binds only loopback ports. No login or public multi-tenant operation is provided.

Reports preserve check evidence, correction history, review decisions, durations, iteration counts and cleanup errors. High/critical findings and incomplete acceptance-criterion coverage prevent success even if the reviewer says approve. Model analysis cannot overwrite observed check results. Generated tests can be incomplete or adversarial; a successful result is evidence of these checks and the recorded review, not a correctness or security guarantee.

Official API references consulted: [CrewAI task outputs](https://docs.crewai.com/en/concepts/tasks), [CrewAI LLM configuration](https://docs.crewai.com/en/concepts/llms), [Docker SDK container options](https://docker-py.readthedocs.io/en/stable/containers.html), [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/), and [Next.js installation](https://nextjs.org/docs/app/getting-started/installation). The CrewAI Task contract was also checked through the connected GitHub plugin against its official repository.

Frontend linting uses ESLint, typescript-eslint and React Hooks rules directly. This avoids an unpatched development-only glob dependency in the framework lint preset. Vitest is updated to a patched 4.1 release. The resulting complete npm dependency audit reports zero findings at verification time. Relevant published advisories: [Tinypool worker options](https://github.com/advisories/GHSA-5gmw-xhrv-c9v3) and [braces nested patterns](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
